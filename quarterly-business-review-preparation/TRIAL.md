# Quarterly business review preparation: tried on its invented example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Opus 5.5 (model ID claude-opus-5-5)
- **Date:** 2026-11-09
- **Template version:** 0.1.0

The inputs were the invented example in [example.md](example.md): the settings, success plan, results log, activity figures, notes, last review's commitments, open issues and proposals for "Customer K". No client data was used.

This is the second run on the same example. An earlier run the same day, by Claude Sonnet 5.5, showed where the instructions left room to guess; the instructions and the example's output were revised after review, and the run recorded here was made on the revised instructions. What the earlier run found, and what was changed, is at the end.

The run was a fresh session started from Claude Code with no tools and no access to any file. The template's instructions for an AI assistant and its output format were given as the session's instructions, and the example's eight inputs were sent as one message. The session did not see the example's published output or the earlier run. The model is the same model that applied the review's edits, in a separate session.

This is one run on an invented example. It is not a test in a client environment.

## What was observed

**Completeness.** Every section of the output format was produced, in order, with nothing asked and nothing stopped for; the example's inputs trigger no stop condition. The status counts add up to 4. Progress was recomputed: G1 is (26 - 20.0) / (26 - 18) = 75%; G2 is 46.7% rounded to 47% on the customer's figure and 63.3% rounded to 63% on ours. No percentage above 100 or below 0 was printed. The G5 row was not used and became a question. The price request was quoted under Notes to check and no price appears anywhere.

**The revised rules, as applied.**
- Agenda: every item carries the default leader the instructions now give. The results item also names each goal's owner from the success plan.
- Adoption: route optimisation (3,936 of 4,800 jobs) and technician seats (58 of 64) appear under "Off, unused or partly used" only.
- The proposed depot 3 goal is marked as lacking a baseline and an owner and as overlapping G1, and became question 4.
- The customer's words appear only on the "In their words" line.
- The quarter's name and the send date come from the stated defaults (calendar quarter; Monday to Friday, no holidays listed), and the header says so.

**Difference from the published example.** The statuses, counts, percentages, adoption lists, agenda leaders, the substance of the six questions, the notes to check and the closing line match. The differences:
- This run named the quarter "Q3 2026"; the example writes "third quarter 2026". Both are the calendar-quarter default.
- This run gave the send date with its weekday, "Tuesday 20 October 2026"; the example writes "20 October 2026", as the output format's "[date]" asks.
- This run added sentences the format does not ask for: two lines about the defaults on the "Not supplied" line, a note on G2's status line that the pack does not choose, a sentence on the price under Notes to check, and the goal owners by name in the results agenda item.
- This run pointed out, under People, that two people hold the title "Dispatch lead" and the settings do not say which is invited. The example does not.
- This run gave the monthly commitment's next-quarter due date as "by the 5th of each month"; the example writes "monthly". The template asks for "the recurring due date", which supports either.
- After the closing line, this run added "Notes for you": its own recomputation, and a remark that the run date in the settings (12 October 2026) is earlier than the date of the session (9 November 2026), so the review had already passed. The example's dates are invented and the remark comes from the session's own date, not from the inputs.
- This run set the pack out in plain text with a few bulleted lists; the example sets it out as headed sections with bullets, like the other published examples.

**Facts not in the inputs.** Neither output states a figure that is not in the inputs. The send date (Tuesday 20 October 2026) is worked out from the settings. The quarter's name comes from the dates by the stated default.

**What this run does not show.** It is one run by one model, on an example whose inputs are clean. The stop conditions (an unmatched header, an unreadable date, no success plan) and the new progress wording for a disagreeing figure at or past the target or behind the baseline were not triggered, so how the template behaves there is untested. The acceptance tests in the template remain proposed; none was run as a test.

## The earlier run and what changed

The first run, by Claude Sonnet 5.5 on the same day and the same inputs, produced every section with the same statuses, counts, percentages and questions as the example then published. It found these gaps, which the review confirmed and which were changed before this run:
- The agenda named a leader for only three of six items, so both outputs guessed the rest. The instructions now give a default leader for every item, replaced only by a leader named in the settings.
- The template did not say where a partly used item belongs in the adoption section; that run listed route optimisation and seats in both lists, and the example put route optimisation under "In use". A partly used item now goes in the second list only, and the example was corrected.
- Progress wording for a disagreeing figure that had passed the target, or moved behind the baseline, was not defined. It now reads "at or past the target" or "behind the baseline".
- A proposed new goal with no baseline or owner, overlapping an existing goal, raised no question. It now does.
- "Customer's words" was listed as a result label with no place in the format. It now only ever sits on the "In their words" line.
- The quarter's name and public holidays were not settings. Both now have stated defaults.
- The example dropped the unit on two brief lines; it now keeps it.
